# 公服账号采集

本分支新增「启动公服采集 / 结束采集」，把官方服务器上自己账号的数据采集下来，结束后直接写入启动器的账号库。

## 和私服启动的区别

| | 连接目标 | 登录方式 |
| --- | --- | --- |
| 单机 / 局域网 | 本机私服 | 本地 UID 回调 |
| **公服采集** | **官方服务器** | **你自己的渠道账号正常登录** |

公服采集**不会**把本地 UID 注入官方客户端，也不绕过官方认证。UID 在这里只是本地数据库的账号身份。

## 使用流程

1. 以管理员身份运行启动器（采集官方流量需要 PktMon，必须管理员）。
2. 选择单机或局域网模式，确认「启动设置」里的 UID（这个 UID 会在采集包缺少 UID 时用于建档）。
3. 点「启动公服采集」，看到「采集已开始」。
4. 启动官方客户端，用**你自己的渠道账号**正常登录，进入游戏场景。
5. 逐项打开要保存的界面：角色、穿搭染色、背包、武器装备、任务、宠物、好友、邮件、抽卡记录、成就图鉴。分页内容逐页打开。
6. 进入自己的家园，等家具加载完整。
7. 回到启动器点「结束采集」。

启动器会自动停止抓包、转换 PCAP、解码，并定位 `account_玩家名_UID.zip`。

## UID 规则

- 采集包里有 UID → **用采集到的 UID** 建档并登录。
- 采集包没有 UID → **用你在启动器里填的 UID** 建档。
- 目标 UID **已有存档 → 判为冲突**，不写入，界面会显示已有账号的昵称与等级。

冲突时不会覆盖任何数据。需要覆盖请先自行备份该账号，或换一个 UID。

## 产物位置

```
profiles/<模式>/db/lolo.db          账号库（账号、存档、基础信息）
profiles/<模式>/accounts/<UID>/     原始响应与导入报告
runtime/capture-sessions/<时间>/    原始 ETL、PCAP、解码输出
runtime/capture.log                 采集日志
```

原始抓包含登录令牌与好友资料，只留在本机，不要外传。

## 依赖

需要 `backup-tool/`（本分支已更新到 1.0.5）以及 TShark。免配置便携包自带 Python 运行时与 TShark；自行部署时设置 `OVERFIELD_TSHARK` 或把 TShark 放到 `backup-tool/tools/tshark/`。

检查环境：

```powershell
python official_capture.py status
```

返回 `ready: true` 表示可以采集；`problems` 会列出缺少的组件或权限。

## 已知限制

- 只能保存客户端实际收到的数据，不是服务端全量导出。
- 必须管理员权限；普通权限会明确提示，不会静默失败。
- 采集期间不要同时开私服模式，避免客户端连到本机。
- 协议与端口按现有国服记录配置（TCP 11001–11004、21001、21002），渠道或版本变化时需要调整。
- 官方客户端版本兼容性未在本次改动中实测，不保证所有版本可用。

## 测试

```powershell
python -m unittest test_official_import test_launcher -v
```

`test_official_import` 使用合成数据覆盖：采集 UID 优先、缺失时回退登录 UID、显示 UID 优先于内部 ID、冲突拒绝写入、导入后其他账号不受影响、ZIP 路径安全。
