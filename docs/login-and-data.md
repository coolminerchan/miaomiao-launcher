# 外部账号登录与玩家数据获取

本文将“外源登录”区分为**官服原账号登录**、**本地私服 UID 登录**和**渠道服登录**。并不表示已实现外服/国际服接入、第三方账号迁移认证或 Token 重放。说明依据本仓库启动器和用户提供的备份工具源码；未读取或核实另一个历史会话的内容。

渠道服（如 MuMu 模拟器渠道）的抓包与保存经验单独见 [渠道服登录与数据保存经验](channel-login.md)。

## 1. 官服登录：用正常客户端和自己的账号

备份工具不代替渠道 SDK，不提供密码登录、扫码认证或绕过服务器校验。先关闭本地私服代理/转发，使原国服 PC 客户端恢复正常官服连接；以管理员身份开始账号抓包后，再退出重开客户端，正常登录自己的账号并进入游戏场景。

抓包应在重新登录前开始，才能看到初始化响应。没有合法账号登录、或服务端已经不再提供这些响应时，工具不能凭 UID 获取远程完整存档。

## 2. 本地私服登录：本地 UID 回调 + 游戏连接重定向

这是日常实际使用的登录方式，不需要官服账号、不联网认证，直接在本机进入游戏。

### 做法

1. 启动器「单机模式」里填入本地 UID（任意数字都行，建议用自己记得住的）。
2. 点「更改目录」，选中本地 PC 客户端安装目录。
3. 点「启动单机游戏」。首次会复制独立客户端副本，需要等一会儿。
4. 游戏启动后会出现原渠道账号弹窗，**不用登录，直接关掉**，或点「进入游戏」即可进本机服务。

### 原理

启动器在独立客户端副本中用 `LocalUidSDK.dll` 替换 `PCGameSDK.dll`，通过 `LOLO_SDK_UID` 返回所选 UID。`SDKLogin` 等回调使用本地占位 `accessToken=local-session`，不是官服访问令牌。调度连接根据 `LOLO_DISPATCH_HOST` / `LOLO_DISPATCH_PORT` 重定向至本地服务；服务管理脚本准备独立模式目录与 UID 网关。

### 已知现象

- 渠道账号弹窗来自原 PC SDK，属正常现象，不影响进入本机服务。
- 游戏标题和「进入游戏」界面仍显示原样，不必担心。
- 启动器不修改系统代理，其他应用网络设置不受影响。
- 已在 B 站 PC 版 1.1.12 上验证，其他版本不保证兼容。

这是私服本地身份机制，不会向官服验证该 UID 的账号所有权，也不会自动拉取官服数据。新模式只建立空数据库架构，不自动复制服务模板中的账号；已有私人存档不变。想恢复自己的角色进度，仍需先按第 1 节备份官服数据，再按第 4 节导入。

本地 UID 模式不能作为公网安全认证，也无法禁止他人手动输入相同数字。在独立空数据库中，同号只是另一个本地测试账号，不会获得原账号的官服权限或进度。但如果主机导入了私人存档并向不可信玩家开放 UID 网关，知道 UID 的人可能访问该主机上的同号存档；当前版本不提供密码或账号所有权校验。保护方法是不要公开私人主机或存档，不是将某个真实 UID 硬编码到公开黑名单。

## 3. 数据获取链路

`PktMon → capture.etl → capture.pcapng → TShark TCP 双向重组 → PacketHead/Body → Raw Snappy（flag=1） → Protobuf → export/raw 与 export/json`

- 当前默认仅抓 TCP 11001–11004、21001、21002；版本/区服端口变化时需同时核对抓包筛选和解析器方向判定。
- TShark 重组乱序、重传和分片，解析器按消息编号查协议类型。
- 数据仅来自客户端实际收到的内容，不是服务端数据库全量导出。运行成功或生成 ZIP 不代表完整备份。
- 打开角色、穿搭/染色、背包、武器装备、任务、宠物、好友、邮件、抽卡历史、成就图鉴等界面并等待加载；分页和详情需逐页打开。
- 切换需要备份的家园预设并进入家园，等待家具加载；多套布局建议分开归档。

结束抓包后核对 `export/summary.json` 的 `player_highlights`、`message_counts`、`unknown_msg_ids` 与 `decode_fallback_count`。主数据应有 `PlayerMainDataRsp`（1006）；宠物看 `GetPetRsp`，家园信息看 `GetGardenInfoRsp`，实际场景家具看 `SceneDataNotice`（1016）。缺项需在有授权且官服正常可用的情况下重新抓取。

注意：当前摘要 `player_highlights.player_id` 取的是内部 ID，不一定等于游戏展示 UID。启动器导入预览优先使用主数据的 `player_label`，回退到 `player_id`，并单独显示内部编号；不要仅凭摘要猜测登录 UID。

## 4. 导入启动器

1. 只压缩本次账号输出的 `export/` 文件夹，确保 ZIP 内路径是 `export/json/..._s2c_...json`。
2. 选择单机或局域网模式，点击“导入数据”，检查 UID、角色名、等级和角色数量，确认后执行。
3. 服务会先停止，原数据库自动备份，其他 UID 保留；导入的账号进度写入当前模式的独立数据库。
4. 用预览所示 UID 登录该模式。单机与局域网进度不自动互通；跨电脑也不自动同步。
5. 核对对应模式 `accounts/UID/import-report.json`，区分已恢复字段与仅留存的原始响应。

解析器能导出某种响应，不等于当前服务端能恢复该功能。任务、活动等模块需按导入报告和目标服务端实现核对，不能承诺百分之百迁移。

## 5. 家园单独备份的范围

家园提取器从 `SceneDataNotice` 查找 `scene_id=9999` 的场景与家具，按 `channel_id` 或 `channel_label` 归档屋主标识。同一标识保留家具数更多的一份；数量相同保留解析遍历中后出现的一份，不能保证跨 TCP 流的严格时间排序。

空家具家园会被跳过，昵称不一定可获取，屋主标识推断也依赖当前协议。该输出是 `SceneGardenData` 二进制/JSON 与索引，不是完整账号备份，也尚无启动器一键导入入口。仅保存自己或获屋主许可、正常拜访可见的资料。

## 6. 隐私边界

原始 ETL/PCAP 可能包含登录令牌、UID、IP、设备信息及好友资料。解码器跳过已知登录请求并去除一个已知登录响应令牌字段，**不保证原始抓包、所有未知消息或整个导出匿名化**。

本人归档保存在可信位置；公开传播的是干净工具，不是 `output/`、导入 ZIP 或存档。不要用其他人的 Token、抓包或 UID 冒充账号。仓库和发布附件必须排除抓包、导出数据、数据库、日志、管理密钥和个人配置。
