## 安卓独立使用，不是 Windows 程序

这是在安卓手机上独立安装和使用的第三方应用，不是 Windows 启动器的组件，也不随 Windows 程序自动安装。不能把 Windows 的代理/VPN 采集步骤套用到它：静态审查显示其通过 shell 权限读取游戏日志中的登录信息，再主动连接游戏网关、登录和查询，输出协议响应 JSON/ZIP；它不是 VPN 抓包器，也不是整个游戏目录或系统级存档镜像。

用户自行决定是否安装与授权；本项目没有替用户运行或安装它。**“免 root”不等于无需高权限**：免 root 路径仍需要 ADB 或运行中的 Shizuku 服务及相应授权，仅安装 Shizuku 管理器不代表服务已启动或权限已授予。

## 权限与兼容性限制

- 静态清单最低 Android 8（minSDK 26），目标 Android 13（targetSDK 33）。最低安装版本不是功能可用性承诺。
- 内置本地 ADB 的 ELF 架构已确认是 **AArch64（ARM64）**；这不代表所有“64 位设备”均可用，尤其不能据此承诺 x86_64 兼容。此架构结论针对内置 ADB，不是对整个 APK 各路径的真机支持认证。
- 无线 ADB 配对通常要求 Android 11 或更高及厂商开放无线调试；Android 8–10 不能仅凭满足最低安装版本便假定可无线配对，需要其他可行的 Shizuku 启动方式。
- 原版把本地 ADB 写到应用可写私有目录后执行。结合 Android 10+ 的应用目录执行限制，存在执行被拒的兼容性高风险；这是平台规则与静态代码交叉推断，**不是已完成真机失败复现**。本轮按用户原包要求保留，未修复。
- 厂商系统、英文配对界面、多设备网络、IPv6/mDNS 环境，以及不同渠道与国际服未完成实测。界面显示渠道名称不等于该渠道认证和协议已经验证可用，不能承诺与 Windows 两服采集具有相同兼容范围。
- 清单声明网络、Shizuku、悬浮窗与请求安装应用等权限，另含无障碍配对服务。权限声明本身不能证明每项功能实际使用或其安全性。

## 必须先了解的隐私与账号风险

1. **无障碍并非只读配对码。** 静态代码确认：服务先递归读取活动窗口的全部文本并以 `OFPair` 标签写入明文 logcat，之后才判断是否包含“配对码”；没有在读取和日志之前按可信设置包过滤。聊天、账号或配对信息可能因此进入诊断日志。这不代表任意普通应用都能读取 logcat，但 shell、授权 ADB 或诊断日志接收者可能读取。服务还包含全局导航动作。
2. **备份会主动登录，可能顶号、停止游戏和切换家园频道。** 这不是完全无干扰的旁观采集。界面的“只读查询”不能证明全部请求无服务端副作用，更不能保证没有账号风控或封禁风险；多个登录组合的探测也不能当作安全保证。
3. **备份可能包含凭据与个人信息，应仅私下处理。** 原版从日志提取 token 等登录信息，并导出请求/响应、角色资料与网关信息；当前没有完成真实样例的令牌清除验证。Base64 是编码而不是加密，不能把导出假定为已脱敏。不要将原始 ZIP/JSON、诊断日志或截图发到公开群、公开 issue 或 Release。
4. 原版会向公共下载位置、应用目录等保存多个未加密副本；分享一个 ZIP 不代表其他副本不存在。使用者应自行检查并妥善清理敏感副本，完成后关闭无障碍、无线调试并撤销不再需要的配对/授权。Shizuku 在重启后可能需要重新启动。
5. 未完成 native ADB/内置 Shizuku 全面审计、签名信任链审查、真机兼容测试或服务端副作用验证。没有已确认的自动第三方收集服务器证据，**也不能据此宣称“完全无外传”或已安全认证**。

## 输出不能直接导入当前 Lolo

原版主要输出 `player-<uid>-<timestamp>.json`、摘要 TXT 与 ZIP，JSON 中使用 `requests`、`responses`、`pairs`、`timeline` 等协议快照结构。它不是当前 Lolo 的 gzip JSON 主存档，不能靠改扩展名、解 ZIP 或复制文件便直接导入或恢复。

接入当前 Lolo **需要独立适配器**，验证格式版本、请求/响应方向、压缩与协议语义、业务字段映射、类型和敏感数据，再用经授权的样例测试。字段名 `decoded` 不等于已经解压的业务数据；原版不能被宣传为已完成 Lolo 导入支持。备份是本次收到的消息集合，不保证全量账号、完整家具或完整历史数据。
