# 渠道服登录与数据保存经验（以 MuMu 模拟器渠道为例）

## 先说清楚

渠道服太多了，本篇**只提供本人经验**，不是通用教程。作者使用的是 **MuMu 模拟器渠道服**，数据保存是在模拟器上完成的。其他渠道服（B 站、TapTap、应用宝、小米、华为、各个商店包等）的登录方式、配置文件位置、账号体系都不一样，**具体情况具体解决**；遇到差异可以带着本篇思路去问 AI 或查阅对应渠道的说明，不要生搬硬套。

本篇不提供任何绕过渠道认证、伪造令牌或盗用他人账号的方法。

## 为什么渠道服要单独说

官服 PC 端有标准客户端，`backup-tool/` 的抓包流程能直接对着它跑。渠道服则不然：

- 多数渠道**只有安卓包**，通过模拟器运行，不在 PC 客户端那条链路上；
- 走的是渠道自己的 SDK 登录，不是国服 PC SDK；
- 数据在渠道账号下，换渠道/换设备未必能继承。

所以抓包对象从「PC 客户端进程」变成「模拟器里的游戏进程」，需要解决的是**怎么让模拟器的流量被 PktMon 看到**。

## 本人做法（MuMu 渠道）

以下为实际操作顺序，供参考：

1. **先在模拟器里正常登录自己的渠道账号**，确认能进游戏、角色数据加载正常。这一步不涉及任何工具。
2. **关闭可能干扰抓包的软件**，包括本启动器的私服服务、其他代理或转发工具，让模拟器按正常渠道线路联网。
3. **以管理员身份**启动账号备份工具（`1_backup_account.cmd`），看到「抓包已开始」再继续。
4. **在模拟器里重新登录并进入场景**。抓包必须在登录动作之前开始，否则拿不到初始化的 `PlayerMainDataRsp`，也就没有 UID 和基础信息。
5. **逐个打开要保存的界面并等加载完成**：角色、穿搭与染色预设、背包、武器装备、宠物、邮件、抽卡历史、成就图鉴、个人资料等。分页内容要逐页翻，否则只有当前页。
6. **进家园等家具显示完整**再离开。有多套布局时分别切换进去，必要时每套单独跑一次抓包。
7. **回到备份窗口按回车结束**抓包，等待自动转 pcapng 并解码。
8. **核对 `export\summary.json`**：`player_highlights` 应有 UID 与角色数量，`message_counts` 应出现你关心的响应。缺哪项就回到第 3 步，把对应界面打开后重新抓一次。

## 和官服流程的差异

| 项目 | 官服 PC | MuMu 渠道服 |
| --- | --- | --- |
| 抓包对象 | PC 客户端进程 | 模拟器内的游戏进程 |
| 登录方式 | 国服 PC SDK | 渠道自己的 SDK |
| 流量路径 | 直接走本机网卡 | 经模拟器虚拟网卡，需确认 PktMon 能抓到 |
| 端口 | 默认 11001–11004、21001、21002 | 可能随渠道和版本变化，需核对 |
| 数据归属 | 官服账号 | 渠道账号，换渠道通常不继承 |

**最容易卡住的是端口和流量路径。** 如果跑完发现 `summary.json` 里没有 UID、`message_counts` 为空，优先怀疑：抓包期间没有重新登录、流量没经过被监听的网卡、或者游戏端口不在默认列表里。

## 排查顺序

1. 抓包是否在**登录之前**开始的？没在之前开始就重来。
2. 模拟器网络模式是 NAT 还是桥接？部分模式下流量不经过宿主机网卡，PktMon 抓不到。
3. 端口对不对？用抓包文件在 Wireshark / TShark 里看实际连接端口，再对照工具的端口过滤列表。
4. 私服代理有没有关掉？开着的话游戏连的是本机服务，自然没有渠道流量。
5. 输出目录里有没有 `capture.pcapng`？有 PCAP 但没解出内容，说明是解码问题而非抓包问题，可换协议版本重解。

## 其他渠道服怎么办

思路是一样的，变的只是「抓谁」和「端口多少」：

- 找到你所用渠道对应的游戏进程或模拟器网络出口；
- 确认流量能被 PktMon 监听到；
- 确定实际游戏端口；
- 再套用本篇的「先开始抓包 → 再登录 → 逐个界面加载 → 结束核对」顺序。

具体到你的渠道（应用宝、小米、华为、TapTap、各商店包等），配置差异较大，**建议把自己的渠道、模拟器类型、抓不到的现象一起描述给 AI 询问**，比照搬别人的步骤更靠谱。

## 隐私提醒

渠道服的抓包同样可能包含渠道账号标识、登录令牌、设备信息与好友资料。只备份**自己**的账号；导出目录和原始 PCAP 不要公开传播，不要上传到仓库或网盘分享。

把 MuMu 渠道的导出数据导入本启动器时，走的是同样的「只压缩 `export\` 文件夹 → 启动器预览 UID → 确认导入」流程，详见 [登录与数据获取方法](login-and-data.md)。
